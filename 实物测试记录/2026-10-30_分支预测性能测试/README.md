# 分支预测上板性能测试记录

## 测试概况

- 记录日期：2026-10-30（按本次资料整理日期；截图未显示实际烧录日期）。
- 平台：RV32I 三级流水线 CPU，FPGA 上板运行，系统时钟 **27 MHz**。
- 工作负载：CoreMark 1.0，`PERFORMANCE_RUN=1`，自动确定迭代次数后执行 **400 次迭代**；启用 `COREMARK_PROFILE=1` 性能计数器。
- 编译环境：GCC 15.2.0，`-march=rv32i_zicsr -mabi=ilp32 -O2`。本次串口输出与 [此前的诊断版上板记录](../2026-10-20_性能诊断/README.md)均包含 `COREMARK_UART_GAP_CYCLES=540000`、`COREMARK_PROFILE=1`。
- 数据来源：本目录保存的 7 张资源、时序及串口截图。对比基线取自上述 2026-10-20 记录。

## 结果摘要

| 指标 | 此前诊断版 | 本次分支预测版 | 变化 |
| --- | ---: | ---: | ---: |
| CoreMark（Iterations/s） | 28.403353 | **30.887495** | **+8.75%** |
| CoreMark/MHz（27 MHz） | 1.051976 | **1.143981** | **+8.75%** |
| 400 次迭代耗时 | 14.082844 s | **12.950225 s** | **−8.04%** |
| Profile 总周期 | 380,236,702 | **349,656,121** | **−30,580,581（−8.04%）** |
| 平均 CPI（总周期 / 退休指令） | 1.299 | **1.194** | −0.104 |
| 条件分支空拍 | 49,216,962 | **18,636,381** | **−30,580,581（−62.13%）** |

**结论：**在两次诊断版运行的工作负载和计数口径可比的前提下，本次加入分支预测后，CoreMark 吞吐提高约 **8.75%**。总周期减少的 **30,580,581** 拍与条件分支空拍减少量完全相同，说明本次测得的性能收益来自条件分支控制冒险的减少。

## 流水线性能计数器

| 计数项 | 此前诊断版 | 本次分支预测版 | 变化 |
| --- | ---: | ---: | ---: |
| Profile cycles | 380,236,702 | 349,656,121 | −30,580,581 |
| Retired instructions | 292,793,398 | 292,793,398 | 0 |
| Memory wait cycles | 27,735,507 | 27,735,507 | 0 |
| RAW wait cycles | 0 | 0 | 0 |
| Branch instructions | 79,318,021 | 79,318,021 | 0 |
| Taken branches | 49,216,962 | 49,216,962 | 0 |
| Branch bubble cycles | 49,216,962 | 18,636,381 | −30,580,581 |
| Jump bubble cycles | 10,490,835 | 10,490,835 | 0 |

本次周期账目可完整对上：

```text
292,793,398  退休指令
 27,735,507  访存等待
          0  RAW 等待
 18,636,381  条件分支空拍
 10,490,835  跳转空拍
-----------
349,656,121  Profile 总周期
```

按“每次条件分支预测错误造成 1 拍空拍”的当前计数口径估算，预测错误率约为 `18,636,381 / 79,318,021 = 23.50%`，对应预测正确率约 **76.50%**。这是从空拍计数推得的比率，应以 RTL 计数器定义为准。条件分支空拍占本次总周期约 **5.33%**，此前约 **12.94%**。

## 解释与记录边界

- 两次退休指令数、分支数、实际跳转数、访存等待及无条件跳转空拍完全一致，支持“运行了同一工作负载”的比较；CRC 也一致。
- 此前没有分支预测时，条件分支空拍数恰好等于实际跳转次数；本次计数值降至 18,636,381。性能增益与减少的分支空拍逐拍对应。
- 这里比较的是**同样开启性能诊断的两次上板运行**。诊断计数和 UART 输出会影响程序执行，不应把这里的数值直接当作关闭诊断功能后的正式 CoreMark 成绩。
- 截图未提供本次烧录 bitstream 的文件哈希或完整原始串口日志，因此只能依据截图记录此次实测结果，无法从这些材料单独证明烧录文件的精确版本。
